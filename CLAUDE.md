# CLAUDE.md

Read `GOALS.md` first. It defines what this repo creates, what is out of scope
and the definition of done. When a choice is unclear, pick the option that makes
the "backups you can prove restore, with measured numbers" story clearer.

## Context

- This repo (joheee/PgPhysicalBackup) is portfolio project #3: physical
  PostgreSQL 17 backups with pgBackRest to Amazon S3, plus a throwaway
  `restore` container that runs the restore scenarios in GOALS.md (latest,
  point-in-time, integrity, failure alerting, extras) and reports pass/fail,
  restore time and RPO. The demo runs locally with Docker Compose.
- The Compose kit (`pg`, `backup` cron container, `start.sh`, `restore.sh`,
  `configs/*.conf.tmpl`) already works. Change it carefully and keep
  `start.sh` and `restore.sh` working the way the README describes.
- Three services: `pg` (Postgres with pgBackRest inside, archives WAL),
  `backup` (cron, shares `pg-data` and the socket) and `restore` (Compose
  profile, run on demand, exits when done). There is no
  always-on second database. Compose project name is `pgdemo`; containers are
  `pg`, `pg-cron-backup` and (optional, profile `pgadmin`) `pgadmin`. Host
  ports: `pg` on `127.0.0.1:5434`, pgAdmin on `127.0.0.1:5435`. pgAdmin
  reaches Postgres as host `pg`, port `5432`.
- The drill (`drill/run.sh`) is self-contained: it seeds its own
  data on a throwaway stanza under `drill/<run-id>/` and never touches the real
  stanza. Its source is a throwaway `drill-source` container (own Compose
  profile) that the script starts and removes; it drives the `restore`
  container once per scenario through env vars and an `EXPECT_FILE`.
  Don't make anything depend on a long-running server, DigitalOcean (paused)
  or project 4's EC2.
- AWS (S3 bucket, IAM policy and user) is set up by hand and documented in
  the README "AWS setup" section. There is no Terraform in this repo. The GitHub OIDC
  provider already exists in the account (stretch goal only); reuse it, don't
  create another.
- Region `ap-southeast-2` only (org SCP). The SCP also denies
  `ec2:DescribeInstances`; don't add anything that needs it.

## Layout

- Repo root: the Compose kit (`docker-compose.yml`, `start.sh`, `restore.sh`,
  `.env.example`, `pg/`, `backup/`, `restore/`, `configs/`).
- `backup/`: `entrypoint.sh` (writes the root-only job env file and the
  schedule-only crontab, prints the startup table, starts the countdown),
  `run-job.sh` (wraps every cron job: logs, alert, ping), `status.sh` (next
  run times from the crontab) and `countdown.sh` (`<seconds>` for log lines,
  `--live` for an in-place line).
- `restore/`: the throwaway restore container. `entrypoint.sh` (preflight,
  restore, start, wait, checks, report, cleanup), `checks.sh` (generic checks
  and the `EXPECT_FILE` checks), `report.sh` (JSON + Markdown). It restores into
  the named volume `pgdemo_restore-data`, never `pg-data`. Reports go to
  `reports/` (git-ignored, created mode 1777 by `start.sh`).
- `configs/*.conf` and `configs/s3-keys.env` are generated by `start.sh`
  (git-ignored). `s3-keys.env` exists only when static S3 keys are set.
- `README.md`: all documentation lives here (quick start, AWS setup with the
  bucket settings and IAM policy, alerting, operations, troubleshooting,
  roadmap). Keep it in step with what is built; don't claim measured numbers
  that haven't been measured.
- `drill/`: `run.sh` (must-haves by default, `--scenario all` or a comma
  list, `--keep`), `seed.sql` (orders, canary, schema_migrations) and
  `listener.py` (stand-in webhook and dead-man's switch on the Compose
  network). Reports go to `reports/drill-<run-id>/`.
- `docs/`: `benchmark.md`, `reports/` (sample reports), runbooks if the
  README gets long.
- `.github/workflows/`: `checks.yml` (lint and validate, no AWS). Optional
  stretch: `restore-drill.yml` (weekly and manual against S3 through OIDC).
  No MinIO.

## Working rules

- Never commit secrets, `.env`, generated `configs/*.conf` and
  `configs/s3-keys.env`, or `pg-data/`. Commit `*.example` files.
- No AWS access keys in the repo or GitHub. Locally, the scoped IAM user's
  key lives only in the git-ignored mode-600 `.env`; on EC2 use an instance
  profile; CI (if added) uses OIDC. The drill uses a random cipher
  passphrase per run. A real stanza's passphrase never enters the repo or
  Actions logs; mask anything sensitive with `::add-mask::`.
- Don't write secrets into world-readable files or command lines (cron
  files, `ps` output, logs).
- Least privilege: scope IAM to the bucket and prefix (`drill/*` for CI, one
  stanza prefix per host). Explain any `"*"` resource in a comment. OIDC
  trust pins this exact repo and the `master` branch (or a PR subject for
  read-only work); never `repo:joheee/*`.
- Tag every AWS resource you create by hand with `project` and `environment`
  and note it in the README "AWS setup" section.
- Pin image tags (with digest) and the pgBackRest package version.
- Restore targets must be empty: never let `initdb` run before a restore,
  and never wipe a data directory without a confirmation or `--yes`. The one
  exception is the restore container clearing its own `pgdemo_restore-data`
  volume after a run that started empty (never after `RESTORE_DELTA=1`, and
  never anything mounted from `pg-data`), and `drill/run.sh` removing the
  volumes it created itself (`pgdemo_drill-*`); it refuses to start when they
  already exist. A
  restored copy runs with `archive_mode=off` so it can't write into the
  source stanza; PITR uses `--target-action=promote`.
- Never put S3 lifecycle rules on live stanza paths; pgBackRest retention
  owns them. Lifecycle rules only cover `drill/` and noncurrent versions.
- Backup jobs fail loudly: non-zero exit, output in `docker logs`, webhook
  alert, dead-man's switch ping on success.
- Cost: flag anything that adds standing cost. Drill objects expire through
  the lifecycle rule; the 10 GB benchmark runs once, by hand.
- Run `shellcheck`, `hadolint`, `actionlint` and `docker compose config`
  before every commit. `hadolint` and `actionlint` are not installed on the
  host; run them as images: `docker run --rm -i hadolint/hadolint < Dockerfile`
  and `docker run --rm -v "$PWD:/r" -w /r rhysd/actionlint:latest`. For compose
  use `docker compose --env-file .env.example config -q`.
- Never delete a stanza, delete S3 objects or change the bucket or IAM
  settings without being asked; show the exact command first.
- Commits: author `joheee <johevinblesstowi07@gmail.com>`, no Co-Authored-By
  trailer. Ask before committing or pushing.
- Tick the boxes in the GOALS.md "Definition of done" as items are finished.
- When reviewing `.env`, mask secret values; never print the passphrase, keys,
  passwords or webhook URLs.

## Gotchas learned (read before touching the kit)

- pgBackRest does not expand `${VAR}` in config files. The passphrase must be
  the `PGBACKREST_REPO1_CIPHER_PASS` env var and the keys
  `PGBACKREST_REPO1_S3_KEY` / `PGBACKREST_REPO1_S3_KEY_SECRET`. An env var
  that is set but empty is an error (`must have a value`), so the key file
  `configs/s3-keys.env` must not exist at all in instance-profile mode.
  `PGBACKREST_*` variables that are not pgBackRest options (the cron
  schedules) only produce harmless warnings on manual `docker exec`.
- `POSTGRES_PASSWORD` and `POSTGRES_INITDB_ARGS` (data checksums) apply only
  when `pg-data` is first created. Changing `.env` later does not change an
  existing cluster; use `ALTER USER` (read the value with `printenv` inside
  psql, never on a command line). Data checksums need a fresh `pg-data`.
- Docker creates a missing bind-mount source as `root:root`. Generate
  `configs/*.conf` before `docker compose up`; `pgadmin-data` must be owned by
  uid 5050; `pg-data` is uid 999, mode 700. To inspect or wipe root-owned
  dirs use a throwaway container, scoped to the one path:
  `docker run --rm -v "$PWD/pg-data:/d" --entrypoint sh postgres:18-alpine -c '...'`.
- `key-type=auto` hangs probing the EC2 metadata endpoint when not on EC2;
  `start.sh` picks `shared` when static keys are set and `auto` otherwise.
- `docker logs` can only append lines. A `\r` redraw with no newline returns
  nothing, and `--log-driver none` disables `docker logs` entirely. In-place
  display lives in `countdown.sh --live` (exec session). Log rotation is by
  size only; keep `max-size` proportional to `COUNTDOWN_INTERVAL_SECONDS`
  (148 B per line with the `local` driver).
- Failure-path tests don't need S3: point `ALERT_WEBHOOK_URL` and
  `HEALTHCHECK_URL_*` at a stand-in listener container on the Compose network
  (the host firewall drops container-to-host traffic), use a fake bucket or
  fake keys, and remove the throwaway `.env` afterwards.
- The restore container runs `docker compose run --rm restore`, so it exists
  only during a run. pgBackRest fetches every file with its own S3 request: a
  22 MB cluster (966 files) took 240 s with one worker and 59 s with four, so
  keep `PGBACKREST_PROCESS_MAX` above 1 for restores. A delta restore of the
  same backup took 7.7 s.
- The restore image ships jq 1.6: `label` (and `$label`) is a reserved word, so
  use other names in jq programs. `--db-include` only takes user databases;
  the real stanza has none (only `postgres`), so that scenario needs the drill's
  `appdb`.
- A targeted (PITR) restore needs a commit after the target time in the
  archived WAL, or Postgres refuses to finish. To test against an idle
  database, record a time T, run `SELECT txid_current()` (a commit), create a
  restore point, `pg_switch_wal()` and `pgbackrest check`, then restore with
  target T.
- zsh aborts a whole command when one glob matches nothing (`rm -f a* b*`); use
  `find ... -delete` for clean-up.
- Compose interpolation reads the shell environment before `.env`; the drill
  relies on that to point the `restore` service at its own stanza, path,
  passphrase and volume. `pgbackrest stop` on the source makes `archive-push`
  fail, which is how the drill stops archiving without changing
  `archive_command` (a `-c` flag beats `ALTER SYSTEM`).
- Do not use `pkill -f <pattern>` when the pattern also appears in your own
  shell command line; it kills the shell.
